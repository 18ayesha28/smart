# Smart NeuroCare: AI-Powered Brain Tumor Detection & Intelligent Hospital Recommendation System

> **Disclaimer (applies to the whole platform):** All AI outputs (detection, classification, segmentation, severity scores, cost estimates) are decision-support tools only. They are **not a substitute for professional medical diagnosis, treatment, or advice**. Every report generated by the system must display this disclaimer, and final clinical decisions must be made by a licensed physician.

### 1.2 Key Architectural Principles
- **Separation of concerns:** ML inference is an independently deployable microservice (own repo, own CI/CD, own scaling) so models can be retrained/swapped without touching the core backend.
- **Async pipeline:** MRI upload → job queued → worker runs preprocessing + inference → result written to DB → client polls/gets websocket push. This avoids blocking HTTP requests during heavy GPU inference (can take 5–30s).
- **Event-driven side effects:** Report generation, hospital recommendation, and cost estimation are triggered as downstream consumers of a `TumorAnalysisCompleted` event, not tightly coupled function calls — enables independent scaling/failure isolation.
- **Zero-trust data access:** PHI (Protected Health Information) is encrypted at rest (AES-256) and in transit (TLS 1.3); access is role-based (RBAC) with full audit logging.
- **Multi-tenant ready:** Hospital/specialist data is modeled so multiple partner hospitals can onboard without schema changes.

## 3. ML Pipeline Design

### 3.1 Datasets (public, for prototyping — clinical deployment needs licensed/IRB-approved data)
- **BraTS (Brain Tumor Segmentation Challenge)** — multimodal MRI (T1, T1ce, T2, FLAIR) with expert segmentation masks (glioma-focused). Best for segmentation model training.
- **Figshare Brain Tumor Dataset** — 3,064 T1-weighted contrast MRI images labeled glioma/meningioma/pituitary. Good for classification.
- **Kaggle "Brain MRI Images for Brain Tumor Detection"** — binary tumor/no-tumor, useful for initial detection baseline.
- **TCIA (The Cancer Imaging Archive)** — larger, more clinically diverse collections.

> ⚠️ Production note: public datasets are useful for prototyping but are not sufficient for clinical-grade deployment. Real deployment requires partnership with hospitals for IRB-approved, de-identified data and regulatory clearance (e.g., FDA 510(k) / CE marking as Software as a Medical Device).

### 3.2 Pipeline Stages

**Stage 1 — Preprocessing**
```
Input (DICOM/NIfTI/JPEG/PNG)
  → DICOM → NumPy conversion (pydicom / SimpleITK)
  → Skull stripping (optional, e.g., HD-BET)
  → Resize to fixed input size (e.g., 224x224 or 256x256)
  → Denoising (Gaussian/median filter or N4 bias field correction for MRI)
  → Intensity normalization (z-score or min-max per scan)
  → Data augmentation (train only): rotation, flip, elastic deformation, intensity jitter
```

**Stage 2 — Detection (binary: tumor / no tumor)**
- Architecture: EfficientNet-B0 or ResNet-50, pretrained on ImageNet, fine-tuned on brain MRI.
- Output: sigmoid probability → threshold (tunable, default 0.5, but favor high recall/sensitivity given medical context).
- Loss: Binary cross-entropy with class weighting (tumor datasets are often imbalanced).

**Stage 3 — Classification (if tumor detected)**
- Multi-class: glioma / meningioma / pituitary / other.
- Architecture: Same backbone family, multi-class head (softmax), or a separate fine-tuned model.
- Loss: categorical cross-entropy, optionally focal loss for class imbalance.

**Stage 4 — Segmentation**
- Architecture: U-Net (2D) or 3D U-Net / nnU-Net for volumetric MRI stacks.
- Loss: Dice loss + Binary Cross-Entropy (combo loss is standard in MONAI recipes).
- Output: pixel-wise binary mask of tumor region per slice (or 3D volume mask).

**Stage 5 — Size & Volume Calculation**
- From segmentation mask: compute pixel/voxel count → convert to real-world mm² / mm³ using DICOM pixel spacing + slice thickness metadata.
- Report: max diameter (longest axis), area per slice, total estimated volume across slices.

**Stage 6 — Severity Scoring**
- Rule-based + ML hybrid: combine tumor volume, tumor type (grade association, e.g., glioma grades I–IV), location (eloquent vs non-eloquent brain regions), and growth rate (if longitudinal scans exist) into a severity score (e.g., low/moderate/high/critical).
- This should be framed as a **decision-support score**, validated against radiologist-assigned grades, not an autonomous diagnosis.

**Stage 7 — Patient Similarity**
- Generate an embedding per patient case (tumor type, size, location, demographics, treatment path, outcome) using a small feature-embedding network or simple feature vector + cosine similarity.
- Store embeddings in a vector DB; retrieve k-nearest historical cases with anonymized outcome summaries.

### 3.3 Evaluation Metrics
| Task | Metrics |
|---|---|
| Detection | Accuracy, Precision, Recall (Sensitivity), Specificity, ROC-AUC, F1 — prioritize **Recall** (false negatives are costly) |
| Classification | Macro F1, per-class Precision/Recall, Confusion Matrix |
| Segmentation | Dice Similarity Coefficient (DSC), IoU (Jaccard), Hausdorff Distance |
| Severity scoring | Correlation with radiologist ground truth (Cohen's Kappa for ordinal agreement) |

### 3.4 Modularity for Independent Updates
- Each model (detection, classification, segmentation) is packaged as a **separate versioned artifact** (e.g., `detection-model:v2.3`) served independently via Triton's model repository.
- A **model registry** (MLflow) tracks lineage: dataset version → training run → metrics → deployed version.
- API contracts between ML service and backend are versioned so a new model version doesn't break downstream consumers as long as input/output schema is stable.

## 4. Database Schema (PostgreSQL)

```sql
-- USERS & AUTH
CREATE TABLE users (
    user_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('patient','doctor','hospital_admin','platform_admin')),
    full_name VARCHAR(255),
    phone VARCHAR(20),
    mfa_enabled BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- PATIENT PROFILE
CREATE TABLE patients (
    patient_id UUID PRIMARY KEY REFERENCES users(user_id),
    date_of_birth DATE,
    gender VARCHAR(20),
    address TEXT,
    latitude DOUBLE PRECISION,
    longitude DOUBLE PRECISION,
    insurance_provider VARCHAR(255),
    budget_range VARCHAR(50),
    emergency_contact JSONB,
    consent_data_sharing BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- MRI SCANS
CREATE TABLE scans (
    scan_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES patients(patient_id),
    file_url TEXT NOT NULL,             -- pointer to S3/MinIO object
    file_type VARCHAR(20),              -- DICOM, NIfTI, PNG, JPEG
    modality VARCHAR(20),               -- T1, T1ce, T2, FLAIR
    upload_status VARCHAR(20) DEFAULT 'uploaded', -- uploaded, preprocessing, processed, failed
    pixel_spacing_mm DOUBLE PRECISION,
    slice_thickness_mm DOUBLE PRECISION,
    uploaded_at TIMESTAMPTZ DEFAULT now()
);

-- ANALYSIS RESULTS
CREATE TABLE tumor_analyses (
    analysis_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    scan_id UUID REFERENCES scans(scan_id),
    tumor_detected BOOLEAN,
    detection_confidence NUMERIC(5,4),
    tumor_type VARCHAR(50),             -- glioma, meningioma, pituitary, other, none
    classification_confidence NUMERIC(5,4),
    segmentation_mask_url TEXT,
    tumor_area_mm2 NUMERIC,
    tumor_volume_mm3 NUMERIC,
    max_diameter_mm NUMERIC,
    severity_score VARCHAR(20),         -- low, moderate, high, critical
    severity_details JSONB,
    model_version VARCHAR(50),
    created_at TIMESTAMPTZ DEFAULT now()
);

-- MEDICAL REPORTS
CREATE TABLE reports (
    report_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    analysis_id UUID REFERENCES tumor_analyses(analysis_id),
    patient_id UUID REFERENCES patients(patient_id),
    report_pdf_url TEXT,
    summary_text TEXT,
    disclaimer_text TEXT DEFAULT 'This report is AI-generated decision support and does not replace professional medical diagnosis.',
    reviewed_by_doctor UUID REFERENCES users(user_id),
    doctor_notes TEXT,
    generated_at TIMESTAMPTZ DEFAULT now()
);

-- HOSPITALS & SPECIALISTS
CREATE TABLE hospitals (
    hospital_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255),
    address TEXT,
    latitude DOUBLE PRECISION,
    longitude DOUBLE PRECISION,
    specializations TEXT[],             -- e.g., {'neuro-oncology','pediatric neurosurgery'}
    rating NUMERIC(2,1),
    success_rate NUMERIC(5,2),
    avg_cost_range JSONB,               -- {surgery: [min,max], chemo: [min,max]}
    accepted_insurance TEXT[],
    contact_info JSONB
);

CREATE TABLE specialists (
    specialist_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    hospital_id UUID REFERENCES hospitals(hospital_id),
    name VARCHAR(255),
    specialty VARCHAR(100),
    years_experience INT,
    rating NUMERIC(2,1),
    case_count INT
);

-- RECOMMENDATIONS
CREATE TABLE recommendations (
    recommendation_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES patients(patient_id),
    analysis_id UUID REFERENCES tumor_analyses(analysis_id),
    hospital_id UUID REFERENCES hospitals(hospital_id),
    specialist_id UUID REFERENCES specialists(specialist_id),
    match_score NUMERIC(5,4),
    match_reasons JSONB,                -- {distance: 0.9, specialization: 0.95, cost_fit: 0.7}
    created_at TIMESTAMPTZ DEFAULT now()
);

-- COST ESTIMATES
CREATE TABLE cost_estimates (
    estimate_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    analysis_id UUID REFERENCES tumor_analyses(analysis_id),
    hospital_id UUID REFERENCES hospitals(hospital_id),
    treatment_type VARCHAR(50),         -- surgery, chemotherapy, radiotherapy, follow-up
    estimated_min_cost NUMERIC,
    estimated_max_cost NUMERIC,
    currency VARCHAR(10) DEFAULT 'INR',
    insurance_coverage_pct NUMERIC,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- RECOVERY ROADMAP
CREATE TABLE recovery_plans (
    plan_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    patient_id UUID REFERENCES patients(patient_id),
    analysis_id UUID REFERENCES tumor_analyses(analysis_id),
    stage VARCHAR(50),                  -- pre-op, surgery, post-op-week1, month1, month3...
    milestone_date DATE,
    description TEXT,
    status VARCHAR(20) DEFAULT 'pending'
);

-- SURVIVOR NETWORK
CREATE TABLE community_posts (
    post_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    author_id UUID REFERENCES users(user_id),
    tumor_type VARCHAR(50),
    content TEXT,
    is_anonymous BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE community_comments (
    comment_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    post_id UUID REFERENCES community_posts(post_id),
    author_id UUID REFERENCES users(user_id),
    content TEXT,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- AUDIT LOG (HIPAA requirement: who accessed what PHI, when)
CREATE TABLE audit_logs (
    log_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(user_id),
    action VARCHAR(100),
    resource_type VARCHAR(50),
    resource_id UUID,
    ip_address INET,
    timestamp TIMESTAMPTZ DEFAULT now()
);
```

## 5. API Design (REST)

### Auth
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/mfa/verify`

### MRI Upload & Analysis
- `POST /api/v1/scans` — multipart upload, returns `scan_id`, status `uploaded`
- `GET /api/v1/scans/{scan_id}` — check preprocessing/analysis status
- `POST /api/v1/scans/{scan_id}/analyze` — trigger ML pipeline (or auto-triggered via queue on upload)
- `GET /api/v1/analyses/{analysis_id}` — detection/classification/segmentation/severity results
- `GET /api/v1/analyses/{analysis_id}/mask` — segmentation mask image/overlay

### Reports
- `POST /api/v1/reports/generate` `{analysis_id}`
- `GET /api/v1/reports/{report_id}` — view report
- `GET /api/v1/reports/{report_id}/pdf` — download PDF
- `PATCH /api/v1/reports/{report_id}/review` — doctor annotation/approval

### Hospital & Specialist Recommendation
- `GET /api/v1/hospitals?lat=&lng=&specialization=&max_budget=&insurance=`
- `POST /api/v1/recommendations` `{analysis_id, patient_preferences}` → ranked hospital/specialist list
- `GET /api/v1/hospitals/{hospital_id}`
- `GET /api/v1/specialists/{specialist_id}`

### Cost Estimation
- `POST /api/v1/cost-estimate` `{analysis_id, hospital_id, treatment_types[]}`
- `GET /api/v1/cost-estimate/{estimate_id}`

### Patient Similarity
- `GET /api/v1/analyses/{analysis_id}/similar-cases?k=5`

### Recovery & Caregiver Support
- `POST /api/v1/recovery-plans` `{analysis_id}` → generates staged roadmap
- `GET /api/v1/recovery-plans/{patient_id}`
- `PATCH /api/v1/recovery-plans/{plan_id}/milestones/{milestone_id}`
- `GET /api/v1/caregiver-guidance?tumor_type=&stage=`

### Survivor Community
- `GET /api/v1/community/posts?tumor_type=`
- `POST /api/v1/community/posts`
- `POST /api/v1/community/posts/{post_id}/comments`

### Follow-up / Life Recovery Assistant
- `GET /api/v1/follow-ups/{patient_id}` — upcoming reminders
- `POST /api/v1/follow-ups` — schedule reminder/appointment

> All endpoints require `Authorization: Bearer <JWT>`; patient-scoped endpoints enforce row-level access control (a patient can only access their own records; doctors/hospital admins access only assigned patients).

## 6. Module-wise Implementation Plan (Sprints, ~2 weeks each)

**Sprint 0 — Foundations**
- Repo setup, CI/CD, infra-as-code skeleton, auth service, base DB schema, HIPAA-aware logging/audit setup.

**Sprint 1 — MRI Upload & Preprocessing (Core)**
- Secure upload endpoint, S3/MinIO integration, DICOM parsing, preprocessing pipeline, job queue wiring.

**Sprint 2 — Detection Model (Core)**
- Train/fine-tune binary CNN, serve via Triton/TorchServe, integrate `/analyze` endpoint, confidence thresholds.

**Sprint 3 — Classification + Segmentation (Core)**
- Train classification head, train U-Net, integrate mask generation + overlay visualization in frontend.

**Sprint 4 — Size/Severity + Report Generation (Core)**
- Volume/area calculation from DICOM metadata, severity scoring logic, PDF report generation (template + disclaimers).

**Sprint 5 — Hospital Recommendation Engine (Novel)**
- Hospital/specialist DB seeding, scoring algorithm (weighted: specialization match, distance via PostGIS, cost fit, ratings), recommendation API.

**Sprint 6 — Cost Estimator + Patient Similarity (Novel)**
- Cost model (rule-based ranges by treatment/hospital tier), embedding generation + vector DB integration for similarity search.

**Sprint 7 — Recovery Roadmap + Caregiver Guidance (Novel)**
- Templated roadmap generator by tumor type/severity, caregiver content library (diet, warning signs, post-op care).

**Sprint 8 — Survivor Network + Life Recovery Assistant (Novel)**
- Community posts/comments (with moderation), reminder/notification service, lifestyle recommendation content.

**Sprint 9 — Hardening & Compliance**
- Security audit, penetration testing, HIPAA/GDPR compliance review, load testing, model monitoring dashboards, disclaimers/UX review with clinical advisor.
